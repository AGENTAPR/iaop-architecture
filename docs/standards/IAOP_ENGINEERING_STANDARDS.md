# IAOP Engineering Standards

Binding standards for all Insurance Agent Operating Platform repositories.
Detailed documents are linked from the repository landscape
(`docs/repository-landscape.md`).

## 1. Language & runtime

- Rust stable, pinned via `rust-toolchain.toml` (currently `1.100.0`).
- Edition 2024. `resolver = "3"` for workspaces.
- Axum + Tokio for HTTP services. SQLx (postgres) for persistence.
  utoipa for OpenAPI 3.1 generation. serde/serde_json for (de)serialization.
- Dependencies pinned with `--locked` in CI; lockfiles are committed.

## 2. Architecture

- DDD + hexagonal layering: `domain` -> `application` -> `infrastructure`,
  with `api` (Axum handlers/OpenAPI) at the edge. Enforced by crate
  boundaries in the workspace manifest.
- `#![forbid(unsafe_code)]` in domain and application crates.
- Business rules live in `domain`; `application` orchestrates use cases;
  `infrastructure` holds adapters (DB, HTTP clients, message brokers);
  `api` maps transport to application ports.
- No business domain models in shared libraries (`iaop-rust-common`,
  `iaop-test-kit`). Shared code is technical only: errors, config,
  observability, HTTP middleware, security/JWT, messaging envelopes.

## 3. Service rules

- Each microservice owns its API, domain model, database, migrations and
  versioned integration events.
- Database-per-service. No cross-service DB access, joins, FKs, or shared
  business entities. Cross-context data flows through REST or versioned
  events only.
- Every service exposes `/health/live`, `/health/ready`, and
  `/api/v1/system/info`, plus `/openapi.json` and `/docs` (Scalar UI).

## 4. API contracts

- REST under `/api/v1`. OpenAPI 3.1, generated by utoipa and mirrored in
  `iaop-api-contracts/services/<group>/<service>/openapi.yaml`.
- Errors use RFC 9457 Problem Details (`application/problem+json`) with a
  stable machine-readable `code`. See IAOP_API_CONTRACT_STANDARD.md.
- Request correlation via `X-Correlation-Id` / `X-Request-Id` headers,
  propagated into logs and events.

## 5. Events

- Canonical envelope defined in `iaop-event-contracts/envelope.schema.json`
  and mirrored by `iaop-messaging::EventEnvelope`.
- Every event has `<context>.<aggregate>.<verb>` type, integer
  `eventVersion`, `eventId`, `occurredAt`, `source`, and optional
  `aggregateId`/`aggregateVersion`/`correlationId`/`causationId`.
- JSON Schema 2020-12 per event; see IAOP_EVENT_SCHEMA_STANDARD.md.
- Transactional outbox/inbox is mandatory for DB-backed event production
  and consumption.

## 6. Persistence

- PostgreSQL per service; SQLx migrations in `migrations/` numbered
  `NNNN_description.sql`, applied forward-only.
- See IAOP_DATABASE_MIGRATION_STANDARD.md.

## 7. Security

- OIDC/JWT (Keycloak) bearer auth validated via `iaop-security`; JWKS
  fetched and cached by the service; no shared session state.
- Secrets come from environment/secret stores only; `.env.example` lists
  names, never values. No secrets in code, docs, or commits.

## 8. Observability

- `tracing` JSON logs with correlation IDs; OpenTelemetry traces/metrics
  exported via OTLP when `OTEL_EXPORTER_OTLP_ENDPOINT` is set; no-op
  otherwise (safe default for local dev).
- Health/readiness must reflect real dependency availability (DB ping).

## 9. Configuration

- Typed config via `iaop-config`: env vars with service-scoped names,
  `.env` optional, validation at startup, fail-fast on missing required
  values.

## 10. CI/CD

- GitHub Actions run **only** on pushes to `main`; every triggerable
  workflow carries `if: github.ref == 'refs/heads/main'` at job level.
- See IAOP_CICD_MAIN_ONLY_POLICY.md. No production auto-deploy on merge.

## 11. Quality gates

`cargo fmt --check`, `cargo clippy --all-targets --all-features -- -D
warnings`, `cargo test --locked`, contract validation, and Docker build
must pass before a repository is considered foundation-complete.
